# Phrase binding

The compositor penalises a line break that splits a two-word place name —
`San / Francisco`. This document records how the rule and its weight were
arrived at, and, more importantly, what the evidence does *not* support.

**Status:** shipped. Default weight `1600`. Rule: two particles open
(`san`, `santa`); everything else is an exact bigram.

---

## 1. There is no authority for this rule

Checked 2026-07-24 against primary sources: **Bringhurst**, **The Chicago
Manual of Style** (17th and 18th eds.), **New Hart's Rules**, the **SI
Brochure**, **NIST SP 811**, and **UAX #14**. None of them prescribes keeping
multi-word toponyms together.

The closest published statement is descriptive, not prescriptive — a Chicago
Q&A *observing* that "some typesetters will use a nonbreaking space" for
compounds like `St. Louis` or `Dr. Smith`, and treating those as abbreviation
compounds rather than as place names. Nothing anywhere covers `San Francisco`
or `Los Angeles` as a class.

So this is **an original design decision**, and it is presented as one.

What *is* inherited is the mechanism, and it is inherited exactly:

| Borrowed | From | Verified against |
|---|---|---|
| Finite additive penalties the optimiser may pay | Knuth & Plass 1981 | `tex.web` §157; `inf_penalty = inf_bad = 10000` |
| A graduated table of different penalties for different faults | `plain.tex` | CTAN master, ll. 285–301 |
| A language-scoped table of numeric levels | Liang 1983 | Thesis ch. 4, Table 5 |

Two corrections worth recording, because earlier drafts of this work got them
wrong. **UAX #14 is purely categorical** — it contains no weights of any kind
and must not be cited as precedent for graduated penalties. And **LaTeX2e does
not override plain TeX's widow/club values**; it reproduces them exactly.

Liang is cited for the *form* of the table, not for its rigour: his patterns
were machine-generated by PATGEN against a hyphenated dictionary with a
published error rate. Ours are hand-authored. Same representational strategy,
not the same validation.

## 2. The rule

```
OPEN    particle + any Title-Case word     san, santa
CLOSED  exact bigrams only                 new+York, los+Angeles, mount+Sinai, …
```

The shape was forced by measurement. An open list of fifteen particles was
tested against **3.71M words of natural English** (macOS man pages with roff
stripped, npm package prose, this repo's own docs). Of 91 distinct firings,
**9 bound a genuine place name — 9.9% precision.**

| particle | firings | genuine | typical false hit |
|---|---|---|---|
| `new` | 60 | 5 | "New Media", "New Year" |
| `el` | 11 | 1 | "El Torito" (a CD boot spec) ×10 |
| `mount` | 7 | 0 | "Mount Mode", "Mount Policy" |
| `st` | 5 | 0 | "51 Franklin St, Fifth Floor" |
| `port` | 4 | 0 | "Server Port The port to which…" |
| `san` | 2 | 2 | — |
| `santa` | 1 | 1 | — |
| `los las fort mt cape rio saint` | 0 | — | never fired at all |

`san` and `santa` stay open because they are not English words, so the failure
mode does not exist. Everything else became a literal pair, which **cannot**
false-positive. Seven particles that never fired in 3.71M words are kept only
in closed form, where they are safe by construction.

**That corpus is technical documentation.** It over-represents "Mount Mode"
and "Server Port" and under-represents real place names, so 9.9% is not a
measurement of editorial prose. It is quoted because the direction was
confirmed independently on title-case editorial copy, where the open rule
protected nine spurious pairs in text containing no place names at all.

Three predicate bugs were found and fixed at the same time; each fired at
*any* weight, so they were defects rather than tuning:

- bound across a full stop (`Saint.` → `Later`) — the single best break a
  compositor has;
- bound across a comma (`St,` → `Fifth`);
- an asymmetric case test bound ALL-CAPS tokens (`ST` → `The`).

## 3. The weight

Re-derived on the fixed rule: 85 real paragraphs × 7 measures (24–78ch),
Chromium and WebKit, which agreed on every cell.

| weight | splits | short lines | fill σ | weak ends | false-positive cost |
|---|---|---|---|---|---|
| 0 | 10 | 122 / 2319 | 0.0619 | 101 | — |
| 800 – 2000 | 9 | 122 | 0.0619 | 101 | +0 short, +0 weak |
| 2400 | 8 | 123 | 0.0620 | 101 | +0 / +0 |
| 3200 – 4800 | 7 | 123 | 0.0620 | 101 | +0 / +0 |

`1600` sits inside a plateau — **[800, 2000]** — where the feature is
measurably free on every metric tracked. Higher weights buy more (2400 rescues
a second split, 3200 a third) for +1 short line out of 2320. That is a real
option, declined because the rag outranks the rule here.

### What this number is not

- **Not an optimum.** The metric cannot separate any value inside the plateau.
  An independent test put the indistinguishable band at roughly [2000, 3000]
  on its own corpus; per-book optima across five held-out sub-corpora ranged
  from 600 to 5200. Treat the constant as a conservative point in a flat
  region, identifiable to no better than several hundred units.
- **Not font-independent.** Every ch-denominated number here was measured in
  **Source Serif 4**. Across five typefaces the cost of a rescued split varied
  3.8× (0.055 weak ends per rescue in Georgia, 0.209 in monospace), and the
  weight at which short lines start climbing ranges from 4800 (Source Serif 4,
  Times) to beyond 16000 (monospace). **Do not exceed 3200 without
  re-measuring in Source Serif 4 and Times New Roman** — they are the tightest,
  and Source Serif 4 is the derivation font, so the headroom is 2×, not 6×.
- **Not a large sample.** The derivation corpus contains 10 split events. Each
  ±1 is 10%.

An earlier draft of this feature shipped at 2400 with a source comment
claiming the weight sat below the short-line ladder's first rung and could
therefore never shorten a line. **That was false** — 2400 is three times that
rung. The claim is recorded here because a false justification beside a number
is worse than no justification.

### `numberUnit`

Measured, found to have no supporting evidence in any corpus, **not shipped**.
There is no disabled code path for it either.

## 4. Reproducing this

The harness is committed as `bind-harness.mjs`; the derivation corpus is
`corpus.json`. Weights are injected at runtime via `__TYPESET_BIND__`, so a
sweep needs no rebuild:

```js
import { measure } from './bind-harness.mjs';
const r = await measure({
  paragraphs, phrases: ['San Francisco'],
  measures: [24, 32, 40, 48, 56, 65, 78],
  weight: 1600, engine: 'chromium',
});
```

Run from the repo root — Playwright only resolves there.

Guarded in CI (`tests/engine.spec.ts`):

- an unfittable name at 12ch composes **identically** with the penalty on and
  off — the cost-not-weld property;
- the false positives an open list used to bind produce no hard violation;
- every paragraph reaches a finished state, fallbacks included.

## 5. Known limits

- **Firefox composition determinism is unverified under load.** A test run
  reported non-deterministic composition with a named system font. It did not
  reproduce here — original code, 8 Firefox loads, quiet and under full CPU
  saturation, was deterministic every time — but the report came from a machine
  running six browser suites at once. A metrics-settled gate was added
  defensively (`typeset.standalone.ts`); it is not a verified fix. Any CI gate
  on rag metrics should be engine-scoped.
- **`New Yorker` no longer binds.** It is a demonym, not a toponym, and is not
  in the closed list. This is deliberate.
- **The closed list is small and Anglocentric.** It covers the names that
  appear in the corpora measured. Extending it is safe — a literal pair cannot
  false-positive — but every addition is unmeasured until it is swept.
- **Coverage, not correctness, is now the failure mode.** After the closed
  list, the residual risk is missed binds rather than wrong ones. That is the
  intended trade.
