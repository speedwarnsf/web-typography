# V4 website launch

## Position

Typeset.ts V4 brings typographic care to real web content: linked, styled,
responsive, and updated by frameworks. Free and MIT licensed. Launch as an
opt-in beta with published evidence, not a universal perfection claim.
Existing V3 URLs remain intact. No premium tier or automatic V3 migration.

## Suggested launch copy

Typeset.ts V4 beta is here. Better-composed paragraphs without flattening your
links, bold or italics. React adapters. Opt-in smart quotes and optical hanging.
Semantic list styling. A pinned install and a way for your coding agent to
check its work. Free, MIT licensed. Try your own words: https://typeset.us

## Distribution plan

1. Publish the website, pinned assets, migration guide, capabilities and evidence.
2. Share the real native/V4 comparison and the launch image with developer and
   design communities, with the beta/support boundaries attached.
3. Invite agents to read /for-agents.md and verify one real-page pilot, not
   blindly install an engine across a whole application.
4. Request attributable integration examples and bug reports. Do not manufacture
   testimonials, installs, reviews, or third-party endorsements.

Social sharing remains an owner action; this launch does not post to accounts.
llms.txt and a skill document assist retrieval but do not guarantee discovery.
No new tracking is installed. Agent/human identity cannot be inferred reliably
from download counts. Any later adoption measurement should be aggregate or
explicitly consented, with self-declared installation context.

## Website acceptance

The final local production build passed 457 checks in Chromium 151, WebKit
26.5 and Firefox 151. The matrix covers all three new routes at widths 320,
390, 768, 1440 and 1920; rich source preservation, controls, keyboard tabs,
route ownership transitions, real cross-origin SRI loading, download hashes,
and unchanged V3 pins. Copy-button payloads were intercepted to avoid replacing
the owner's system clipboard; these are not new native clipboard claims.

The served tarball was also installed into an empty temporary consumer and
its ESM/CommonJS version exports verified. Production Next build and TypeScript
checks passed. Engine qualification remains the separate acceptance.json.

Run: npm run build; npm run start -- --port 4205; npm run test:site.
Screenshots and the detailed test report are generated in output/playwright.

The demo follows the release's opt-in hanging default and displays craft
outcomes separately. Its editorial sample applies hanging in Chromium and
Firefox; WebKit retains native layout after hanging verification declines it.
This integration limitation is published in acceptance.json and beside the
demo. Standard rich composition works in all three engines. Root clipping
inherited from the legacy site was removed only for the new routes.

The existing remote V3 CI suite passed its 36 tests on this launch. This does
not substitute for remote V4 engine qualification. A no-Git cloud-build
simulation also verified immutable pins and rejected a deliberately corrupted
copy of a pinned artifact.
